How to fix it on Render

  1. Open your service in the Render dashboard.
  2. Go to the Environment tab.
  3. Click Add, then set SECRET_KEY as the key.
  4. For the value, press the Generate button. Do not type one by hand.
  5. Click Save, then Manual Deploy.

Or set these all at once

Key Value
SECRET_KEY press Generate
APP_ENV production
AUTO_CREATE_SCHEMA true
SESSION_COOKIE_SECURE false
ENABLE_SCHEDULER true

Or generate the key locally

python -c "import secrets; print(secrets.token_urlsafe(48))"
Nothing is exposed while the key is unset: every route except this page and /health returns 503 by design. No session can be created, so there is nothing to sign and nothing to forge.

This is also why a key published in the repository is refused — a known signing key would let anyone sign in as any user. See the repository for the full setup.
